# 分类记忆设计

这个版本把用户的判断拆成两层：

1. **可泛化策略**：只保存不含姓名、金额、日期和完整交易描述的关键词规则，进入源码并可随应用发布。
2. **精确操作记忆**：每次用户在明细页保存分类或消费属性时，以“收支方向 + 规范化交易名称”为键写入浏览器 IndexedDB。下次遇到同一描述时优先复用最近一次判断。

优先级为：当前交易手动覆盖 > 浏览器精确记忆 > 可泛化策略 > 通用关键词分类。

## 从历史操作学习到的稳定偏好

- 房租属于刚需、固定支出。
- 聚餐的核心属性是社交、弹性、娱乐。
- 户外体验的稳定属性是情绪价值和娱乐；成长、奖励、社交等继续按具体场景手动判断。
- AI 工具主要作为长期投资和提升。
- 相机租赁用于形象管理，属性为职场形象、弹性、情绪。
- 网络超市归到日用消耗下的网络超市，而不是泛化为普通生活小物。
- 红包必须先于“包”类商品关键词判断，避免被误分到鞋包。
- 宠物医保、宠物顺风车归到日用消耗 / 宠物用品。
- Blueglass酸奶、可口可乐等明确饮品归到餐饮消费 / 咖啡奶茶；永民手作需同时有餐饮上下文。
- 水果必须有具体商品证据，不能只凭超市名称判断。
- 搬家运费必须同时出现搬家、打包或已确认的搬家上下文。
- 交通月度合并后的名称分别使用“地铁公交”“打车”“共享单车”，避免通用名称造成分类串位。

## 完整收支与退款冲销

- 所有有效收入、支出、退款和资金流转都保留在账单中。
- 退款不计作普通收入；总收入只统计真正的收入行。
- 原支出和退款都保留，通过关联ID和净计入金额冲销，避免退货后仍重复计入消费。
- 相同金额本身不足以匹配退款；必须有唯一订单号，或唯一的商户、平台和日期证据。

旅行、家庭往来、朋友转账、报销和搬家等高度依赖上下文，不固化成宽泛规则，只通过本地精确记忆复用。

## 隐私边界

- 原始账单、金额、联系人、完整商户描述不写入源码。
- GitHub 只保存可泛化策略和记忆机制。
- 精确记忆默认只在当前浏览器 IndexedDB 中；删除账单不会删除记忆。
- 可通过“导入历史分类记忆”读取本应用导出的 JSON。仅 `edited: true` 的记录会被学习，且原始 JSON 不上传服务器。
